# Bounded native commit policy exercise

The [recorded sample](evidence/commit-policy-native-exercise.json) exercises the [fixture policy skill](../tests/fixtures/commit-policy/SKILL.md) with the current native agent. It complements the deterministic configuration, handoff and real-Git tests in `tests/test_commit_policy.py`; it is not an independent fresh-agent or host-lifecycle trial.

Use an isolated temporary checkout, private XDG directories and a local bare remote. Start from a base where `value()` returns one. Add one commit changing it to two and a second documenting that outcome, both by the same fixture author. Pin the base, head, complete history and diff. Supply repository requirements preserving authorship with no required message body, and user constraints permitting only a local rewrite and exact-lease push to that fixture remote.

Select `fixture:commit-policy` privately, resolve its resource and capture the definition through `commit_policy.policy_spec`. Claim the provider under the ordinary task contract without a review cycle. Read the complete pinned context and the fixture skill, then author an original complete provider report containing only grouping/message instructions. Record it, build the handoff and verify it against current inputs. A second start with unchanged provider inputs must return `reuse`.

Apply the returned instructions through cleanup and the explicit-policy path in `dk-workflows:dk-commit-message`. Save a recovery ref, verify ownership and a clean worktree, squash into one commit and use a short imperative subject without a body. Verify exact final-tree equality and authorship, run a real assertion that `value()` returns two, then push only to the fixture bare remote with the saved exact lease. Check that eligible tree-based content review remains reusable. Observe the published fixture head and run the local assertion again for that head.

The recorded run returned a complete policy report, verified the handoff and unchanged-input reuse, reduced two commits to one, preserved the tree and author, and produced the subject `Return two and document usage`. The local lease-protected publication and resulting-head validation succeeded. The native agent interpreted the policy and applied it; no scripted policy interpreter selected the grouping or message.

The provider and cleanup roles shared this implementation session. The content review report was a deterministic stand-in. No separate host execution lifecycle, external skill registry, GitHub publication or GitHub Actions run was observed. Full bundled recipe tests separately cover production helper transports, final-head CI sequencing, repairs, publication receipts and unchanged default cleanup. These boundaries limit the sample's adherence claims.
