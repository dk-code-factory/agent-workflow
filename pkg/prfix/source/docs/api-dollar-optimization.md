# API dollar optimization

The target is the cost of a complete selected workflow and its fresh-session
resume, including preparation, descendants, waiting, finalizers and evidence
consumption. Required coverage, current inputs, original findings, native evidence,
publication recovery and exact-head CI remain correctness constraints.

## Candidates

1. Replace token minimization in current agent guidance with API dollar cost.
   Count fresh input, cache reads and writes, output including reasoning, model,
   context charges and service tier. Keep historical experiments unchanged.
2. Accept a complete prepared checklist in the primary result. Missing checklists
   retain bounded same-agent follow-ups; malformed evidence never consumes a claim
   or check. Preserve primary artifacts, fingerprints and native execution guards.
3. Offer compact prepare/finish responses for assignments already in context.
   Keep complete new-invocation assignments and explicit full retrieval. Include
   any necessary retrieval when measuring savings.
4. Verify existing selective reuse across unchanged inputs, tree-preserving
   cleanup, partial recovery and new-session resume. Stabilize governing content
   before review and refresh actual changed inputs; do not weaken fingerprints.
5. Inspect observed host service controls. Use supported lower-price tiers only
   when available and appropriate to the assigned workflow. Do not add a model
   launcher or silently change personal settings. The development host was already
   configured for Standard, so Fast-to-Standard savings do not apply to that host.

## Validation and adoption

Run focused and complete offline tests on baseline and candidate revisions.
Exercise intact and damaged primary checklist evidence, malformed submissions,
native observation failures, input drift, checklist-only refresh, replay, retained
budgets, unchanged siblings and retrieval from another process.

Freeze sources, guidance, assignments, inputs and host conditions before native
trials. Use existing native tools for controlled fixture invocations; never launch
a model CLI as a fallback. Compare three alternating baseline/candidate pairs for
the combined implementation against the corrected baseline (5.1.5). Attribute savings to
that bundle only. If it fails, isolate candidates in subsequent frozen experiments
before adopting any remaining runtime changes.
Keep every initiated arm and unfavorable result. Missing independent inventories,
terminal outcomes, prices or starting-context controls make adoption inconclusive.

Native fixture workloads exercise complete configured task coordination and
fresh-session recovery with isolated Git and offline domain transports. Stand-in
domain outputs cannot establish the recall of external reviewers or production
GitHub behavior; complete recipe regressions and an actual PR review/CI gate
remain separate requirements. Do not describe fixture measurements as a complete
production PR bill or a universal savings percentage.

Use the existing dollar gate: passing correctness, at least five percent lower
median API-equivalent cost, lower aggregate cost and at least two improving pairs.
Report preparation and experiment implementation spending separately from the
recurring measured task. Deduplicate response identities globally and price each
response using its actual controls. Reasoning is included in output once.

Publish successful, verified changes in reviewable PRs. Merge only after complete
required review, successful exact-head CI and a final current-state audit. The user
explicitly authorized creation and merge of working changes; incomplete evidence
does not satisfy that condition.
