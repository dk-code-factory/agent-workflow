# Route a PR

Read `dk-workflows:dk-pr-iter` through [skill-owned configuration](../docs/skill-configuration.md). `personal_accounts` uses verified host-scoped numeric IDs. `routes.own_pr` and `routes.other_pr` are fully qualified invocation objects with optional additional instructions, native controls and skill options. Pass invocation-local `--options FILE` to the router when supplied. Legacy process route names remain supported for existing saved records.

When effective configuration uses `--upstream HOST/OWNER/REPO`, pass the same option to `pr_route.py`. Otherwise routing reads only user and canonical PR repository settings. The result includes `pr`, `repository`, `head`, `host`, `author`, `actor`, `ownership` (`mine` or `others`), selected `process`, `skill` and complete `invocation`. Its default routes select `pr-fix` and `pr-review`; explicit configured routes select other process names. Resolve the invocation's skill through native tools, preflight requested agent controls and follow the shared [invocation contract](../docs/invocations.md). Identity failures return blocked JSON and exit 2.

Resolve the canonical PR URL from the user's input or checkout. Run `python3 PLUGIN_ROOT/scripts/pr_route.py --pr PR_URL`; it loads effective personal-account settings directly under [workflow configuration](../docs/configuration.md), without invoking `dk-workflows:dk-config`. It compares the author's numeric account id with the authenticated account and configured personal accounts on that host. Remotes, repository ownership, commit authorship and write access do not prove personal PR ownership. Additional accounts, including bots, count as yours only when explicitly configured. Missing or conflicting identity evidence blocks automatic routing.

Report the author, ownership and selected workflow. Invoke `dk-workflows:dk-pr-fix` for your PR or `dk-workflows:dk-pr-review` for another author's PR. An explicit request to review your PR or maintain another author's PR overrides automatic selection. It does not change the author or grant branch permissions. The fix workflow checks permission to write or rewrite separately. Never approve the authenticated account's own PR.

Pass original instructions from the user, repository and private settings, current Decisions and discussion, identity evidence and exact permitted actions to the selected skill. Keep the run id, claims, original results and budgets on resume. Recheck identity and head before remote actions. Saved account mappings select a workflow; they grant no permission to publish, approve or merge. Read-only and narrower user instructions override saved completion policies.

Treat "check out this PR, run dk-pr-iter, then merge it" as one ordered request. Perform the requested checkout without discarding unrelated work and verify the canonical PR and head. Preserve the original merge instruction, source and exact PR in operational progress and each handoff to `dk-workflows:dk-pr-fix` or `dk-workflows:dk-pr-review`. Once that workflow and necessary finalization complete, invoke `dk-workflows:dk-pr-publish` under [merge publication](../docs/pr/publication.md), refreshing the final published head, reviewed target, clean review coverage, verification, CI and repository readiness. An explicit merge request remains authorized across routing and ordinary resume unless superseded; do not stop at workflow completion or require another confirmation solely because automatic merging defaults to disabled. Never transfer this permission to a different PR or add a PR approval. Incomplete review, failed finalization, missing successful CI or other unmet readiness requirements block merging and require a concrete private report.
